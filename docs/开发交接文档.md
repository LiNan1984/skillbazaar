# SkillBazaar 开发交接文档

> 版本: 1.0.0 | 更新日期: 2026-05-02

---

## 一、项目概述

SkillBazaar 是一个 AI Agent/Skill/Cron/Workflow 交易平台，用户可以发布、购买、订阅各类 AI 技能和定时任务，创建自定义智能体并装配已购技能。

**核心定位：** AI 技能市场 + 智能体编排平台

## 六、部署指南

### 6.1 服务器要求

- Python 3.9+
- Node.js 18+
- Nginx (可选，生产环境推荐)

### 6.2 后端启动

```bash
cd /root/skillbazaar/backend

# 安装依赖
pip install -r requirements.txt
# 额外依赖（不在requirements.txt中）
pip install langgraph httpx cryptography

# 启动
python main.py
# 或
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

后端启动后自动执行 `database.init_db()`，创建所有表并初始化默认活动数据。

### 6.3 前端构建与启动

```bash
cd /root/skillbazaar/frontend

# 安装依赖
npm install

# 开发模式
npm run dev
# 默认端口 7788，Vite代理 /api → localhost:8000

# 生产构建
npm run build
# 产物在 dist/ 目录，用 Nginx 托管
```

### 6.4 Nginx 配置参考

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 前端静态文件
    location / {
        root /root/skillbazaar/frontend/dist;
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8000/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### 6.5 Vite 开发代理

`frontend/vite.config.js` 已配置代理：
```javascript
server: {

        '/api': {
            target: 'http://localhost:8000',
            changeOrigin: true,
            rewrite: (path) => path.replace(/^\/api/, '')
        }
    }
```

## 七、关键业务逻辑说明

### 7.1 用户认证

- 注册时生成 `auth_token`（随机hex），存储在 users 表
- 前端所有需要认证的请求通过 `Authorization: Bearer <token>` Header 传递
- 后端通过 `db.fetch_user_by_token(token)` 验证身份
- 用户表同时存储 `coins`（金币余额）

### 7.2 购买流程

1. 前端调用 `POST /products/{id}/purchase`
2. 后端验证用户金币余额
3. 扣除金币，写入 transactions 表
4. 写入 wallet_transactions 流水
5. 返回购买成功

### 7.3 BS导购助手 (LangGraph)

- 使用 `StateGraph` 构建，`MemorySaver` 保持会话
- `AgentState.messages` 使用 `Annotated[List[dict], operator.add]` 累积消息
- 节点：理解意图 → 搜索商品 → 生成推荐卡片 → 格式化回复
- 前端通过 `ChatPanel` 组件交互，支持清除会话
- 聊天历史存储在 localStorage

### 7.4 智能体执行

1. 用户创建智能体，选择已购技能（skill_ids）
2. 运行时，系统构建包含技能信息的 system prompt
3. 调用 LLM API（当前使用 api.finmall.com 的 GLM-5.1）
4. **降级策略：** LLM 不可用时，返回技能链接列表而非报错
5. 记录执行日志到 agent_runs 表

### 7.5 Cron订阅流程

1. 发布者注册 Cron 商品（cron_expression + webhook_secret）
2. 订阅者购买后，系统创建 cron_subscriptions 记录
3. 发布者通过 `POST /cron/push` 推送执行结果
4. 系统验证 webhook_secret，记录执行日志
5. 订阅者通过 `GET /cron/results/{sub_id}` 拉取结果

### 7.6 签到与积分

- 使用北京时间（UTC+8）判断签到日期
- 每日签到10分，连续签到有额外奖励
- 月度任务7个，完成后领取积分
- 100积分可兑换10金币

## 九、已知问题与限制

### 9.1 LLM API 不稳定

- 当前使用的 LLM API（api.finmall.com）偶尔超时或不可达
- 智能体执行已加入降级策略：LLM 失败时返回技能链接
- BS导购助手也会受影响，但 LangGraph 会话不中断

### 9.2 安全相关

- CORS 配置为 `allow_origins=["*"]`，生产环境需限制域名
- auth_token 明文存储在 SQLite，生产环境建议加密
- 无 HTTPS 强制，生产环境需配置 SSL 证书

### 9.3 数据库

- SQLite 单文件，不适合高并发场景
- 无数据库迁移工具，表结构变更需手动处理
- 建议生产环境迁移至 PostgreSQL

### 9.4 功能待完善

- 管理后台（AdminPage）为框架代码，需要完善
- 悬赏市场缺少仲裁/评价机制
- Cron 缺少自动调度（目前仅推送模式）
- 积分兑换比例可配置化
